ISI Distance

f_ISI_distance

ISI-distance.f_ISI_distance(spikes, tmin, tmax, showing, plotting)

F_ISI_DISTANCE Computes the bivariate and multivariate ISI-distance between spike trains.

Calculates the instantaneous and overall Inter-Spike Interval (ISI) distance between multiple spike trains within a given temporal window.

Note

Based on the ISI-distance algorithm proposed by Kreuz et al.

See also

Kreuz T, et al. Measuring spike train synchrony. J Neurosci Methods, 2007.

The instantaneous bivariate ISI-distance profile \(I(t)\) between two spike trains is defined as:

\[I(t) = \frac{|x_1(t) - x_2(t)|}{\max(x_1(t), x_2(t))}\]

where \(x_1(t)\) and \(x_2(t)\) are the instantaneous inter-spike intervals for each spike train at time \(t\).

The overall bivariate ISI-distance \(D_I\) is the time average over the window \([T_0, T_1]\):

\[D_I = \frac{1}{T_1 - T_0} \int_{T_0}^{T_1} I(t) \, dt\]

In the multivariate case, the population profile \(I_{multi}(t)\) is averaged over all \(N(N-1)/2\) pairs:

\[I_{multi}(t) = \frac{2}{N(N-1)} \sum_{<i,j>} I^{i,j}(t)\]

Valid call structures:

% Basic call with default output flags (showing=15, plotting=15)
f_ISI_distance(spikes, tmin, tmax);

% Suppress all plots and console outputs
f_ISI_distance(spikes, tmin, tmax, 0, 0);

% Display only the population profile (console and plot)
f_ISI_distance(spikes, tmin, tmax, 4, 4);
Parameters:

  • spikes (cell) – Cell array where each element is a vector containing spike timestamps for a train.

  • tmin (double) – Lower temporal boundary of the window of interest.

  • tmax (double) – Upper temporal boundary of the window of interest.

  • showing (integer, optional) – Bitmask controlling console output verbosity (default: 15). * +2: Print pairwise ISI distance summary * +4: Print population profile array * +8: Print final pairwise distance matrix

  • plotting (integer, optional) – Bitmask controlling figure generation (default: 15). * +2: (Reserved for pairwise plots) * +4: Plot population profile over time * +8: Plot final ISI distance matrix heatmap

Note

The function requires at least two spike trains (length(spikes) >= 2) to compute pairwise distances.

f_ISI_distance_adaptive_v1

ISI-distance.f_ISI_distance_adaptive_v1(spikes, tmin, tmax, threshold, showing, plotting)

F_ISI_DISTANCE_ADAPTIVE_V1 Computes the adaptive ISI-distance between spike trains.

Calculates the adaptive Inter-Spike Interval (ISI) distance between multiple spike trains using a Minimum Resolvable Time Scale (MRTS) parameter. The MRTS threshold prevents division-by-zero artifacts and stabilizes the distance measure during high firing rate periods or silent intervals.

The instantaneous adaptive ISI-distance profile \(I_{adapt}(t)\) is defined as:

\[I_{adapt}(t) = \frac{|x_1(t) - x_2(t)|}{\max\left(x_1(t), x_2(t), \tau_{MRTS}\right)}\]

where \(x_1(t)\) and \(x_2(t)\) are the instantaneous ISIs of the two spike trains at time \(t\), and \(\tau_{MRTS}\) is the user-defined or automated threshold parameter.

The overall adaptive distance \(D_I\) is obtained by time-averaging over \([T_0, T_1]\):

\[D_I = \frac{1}{T_1 - T_0} \int_{T_0}^{T_1} I_{adapt}(t) \, dt\]

Valid call structures:

% Classic mode (MRTS = 0)
f_ISI_distance_adaptive_v1(spikes, tmin, tmax);

% Automatic threshold selection based on RMS of ISIs
f_ISI_distance_adaptive_v1(spikes, tmin, tmax, 'auto');

% Manual MRTS threshold set to 0.05 seconds
f_ISI_distance_adaptive_v1(spikes, tmin, tmax, 0.05);

% Custom threshold with console/plot display bitmasks
f_ISI_distance_adaptive_v1(spikes, tmin, tmax, 'auto', 15, 15);
Parameters:

  • spikes (cell) – Cell array where each element is a vector containing spike timestamps for a train.

  • tmin (double) – Lower temporal boundary of the analysis window.

  • tmax (double) – Upper temporal boundary of the analysis window.

  • threshold (double or char, optional) – MRTS threshold parameter (default: 0). * 0: Classic ISI-distance mode. * >0: Manual MRTS scalar value. * 'auto': Automated calculation based on the Root Mean Square (RMS) of all ISIs.

  • showing (integer, optional) – Bitmask controlling console output verbosity (default: 15). * +2: Print global ISI distance summary * +4: Print population profile array * +8: Print final distance matrix

  • plotting (integer, optional) – Bitmask controlling figure visualization (default: 15). * +2: (Reserved for pairwise plots) * +4: Plot population profile over time * +8: Plot distance matrix heatmap

Note

If threshold is set to 'auto', the function internally calculates the Root Mean Square (RMS) of all inter-spike intervals:

\[\tau_{MRTS} = \sqrt{\frac{1}{N_{isi}} \sum_{k=1}^{N_{isi}} (\Delta t_k)^2}\]

f_lc_simulated_annealing

Latency_Correction.f_lc_simulated_annealing(trains, tmin, tmax, cost_threshold)

This function computes the optimal shifts for each spike train using simulated annealing to minimize the overall cost.

It uses a pairwise RMSE cost function to evaluate the alignment of spike trains and iteratively adjusts the shifts to find a configuration that minimizes the cost.

Parameters:

  • trains (cell array) – A cell array where each cell contains the spike times for a specific spike train.

  • tmin (float) – The minimum time to consider for spike trains.

  • tmax (float) – The maximum time to consider for spike trains.

  • cost_threshold (float, optional) – The threshold for the cost below which the optimization will stop. If not provided, a default value of 1e-3 is used.

Returns:

  • all_shifts (array) – An array where each element represents the optimal shift for the corresponding spike train.

  • costs (array) – An array containing the cost values at each iteration of the simulated annealing process.

f_synfire

Latency_Correction.f_synfire(tmin, tmax, n_trains, n_correct, n_random, n_inversed, overlap)

Create synfire trains with specified parameters This function generates a set of spike trains that can include correctly ordered events (synchronized spikes), random events, and inversed events (anti-synchronized spikes).

It allows for control over the number of events of each type, the overlap between events, and the total number of spike trains. The step between spikes is calculated based on the overlap parameter, ensuring that spikes are appropriately spaced within the specified time range. It also ensures that random spikes do not overlap with synchronized spikes, and clamps spike times within the specified time range.

Parameters:

  • tmin (float) – The minimum time for spike generation.

  • tmax (float) – The maximum time for spike generation.

  • n_trains (int) – The number of spike trains to generate.

  • n_correct (int) – The number of correctly ordered events (synchronized spikes).

  • n_random (int) – The number of random events.

  • n_inversed (int) – The number of inversed events (anti-synchronized spikes).

  • overlap (float) – A value between 0 and 1 indicating whether to allow overlapping spikes (values <0.5 indicate no overlap).

Returns:

trains (cell array) – A cell array where each cell contains the spike times for a specific spike train. Each spike train is represented as a vector of spike times.

SPIKE_order.pairwise_order(tmin, tmax, spikes, spike_ind1, spike_ind2)

This function computes the pairwise SPIKE-order profile between two spike trains.

A value of +1 indicates that the spike in the first train leads the closest spike in the second train, -1 indicates that it follows, and 0 indicates that they are coincident or no closest spike is found within the coincidence window.

Parameters:

  • tmin (float) – The minimum time for the analysis window.

  • tmax (float) – The maximum time for the analysis window.

  • spikes (cell array) – A cell array where each cell contains the spike times for a specific spike train.

  • spike_ind1 (int) – The index of the first spike train in the spikes cell array.

  • spike_ind2 (int) – The index of the second spike train in the spikes cell array.

Returns:

res (array) – An array where each element corresponds to the SPIKE-order value for the corresponding spike time in the first spike train with respect to the second spike train.

ALGO_Simple.Gen_data.generate_SP_dataset(params)

GENERATE_SP_DATASET Generates synthetic spike trains for Summed Population analysis.

Generates a 3D cell array of simulated spike trains based on input neural population parameters. The generated dataset models multi-neuron responses across multiple stimuli and trial repetitions for Summed Population (SP) benchmarks, including Collective (COLL), Individual (INDI), and Non-Coding neurons.

Valid call structure:

spikes = generate_SP_dataset(params);
Parameters:

params (struct) –

Structure containing dataset generation parameters:

  • N (integer): Total number of neurons in the population.

  • c (integer): Number of collective (COLL) neurons.

  • nIndi (integer): Number of individual (INDI) neurons.

  • S (integer): Number of distinct stimulus conditions.

  • R (integer): Number of trial repetitions per stimulus.

  • Tmax (double): Upper temporal boundary of trial duration (in seconds).

  • rate (double): Baseline firing rate (in Hz).

  • indiJitter (double): Gaussian jitter standard deviation for INDI neurons.

Returns:

  • spikes (cell) – 3D cell array of dimensions [N x S x R] containing spike timestamps.

f_bottom_up_V2

ALGO_Simple.Summed_Population.Algorithms.f_bottom_up_V2(spikes, Tmax, Distances, threshold, showing, plotting, other_figs)

F_BOTTOM_UP_V2 Sequential greedy inclusion algorithm for optimal neuronal subpopulation selection.

Performs a iterative Bottom-Up (forward selection) search to identify the subpopulation of neurons that maximizes the classification performance :math:P. Starting from an empty set, at each step \(k\), the algorithm evaluates all available candidate neurons and permanently includes the one that yields the highest incremental performance.

The computational complexity of this forward selection process is polynomial:

\[\mathcal{O}\left(\frac{N(N+1)}{2}\right)\]

which drastically reduces the evaluation space compared to the \(2^N - 1\) exhaustive search.

  • Tmax (double) – Upper temporal boundary of the analysis window.

  • Distances (0 or 1 array  (e.g [1 0 0 0] for the SPIKE distance)) – Distance metric type (e.g., ‘SPIKE’, ‘RI-SPIKE’, ‘SPIKE_adaptive’, ‘RI-SPIKE adaptative’).

Performs an iterative Top-Down (backward elimination) greedy search to identify the subpopulation of neurons that maximizes the classification performance \(P\). ALGO_Simple.Summed_Population.Simulated_Annealing.metropolis_acceptance(Pcandidate, Pcurrent, T)

METROPOLIS_ACCEPTANCE Evaluates the Metropolis-Hastings acceptance criterion.

Determines whether a proposed candidate subpopulation state is accepted during Simulated Annealing optimization. Moves that improve classification performance (\(P_{\text{candidate}} > P_{\text{current}}\)) are accepted deterministically. Non-improving moves are accepted probabilistically according to the Boltzmann distribution:

\[q = \exp\left(-\frac{P_{\text{current}} - P_{\text{candidate}}}{T}\right)\]

simulated_annealing

ALGO_Simple.Summed_Population.Simulated_Annealing.simulated_annealing(spikes, Tmax, Distances, threshold, paramsSA)

SIMULATED_ANNEALING Optimizes neuronal subpopulation selection via Simulated Annealing.

Performs a global stochastic search to find the subpopulation of neurons that maximizes discrimination performance \(P\). Starting from a random subpopulation, the algorithm explores neighboring states using single-element mutations, accepting non-improving moves probabilistically according to the Metropolis criterion. Includes automatic temperature initialization (\(T_0\)), dictionary-based evaluation caching, exponential cooling, and a re-annealing mechanism triggered upon stagnation.

paramsSA.coolingFactor = 0.90;        % Exponential decay factor (alpha)
